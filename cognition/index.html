What it is

Cognition OS is a multi-tenant service that stores and reasons about knowledge graphs. Every organisation gets its own isolated graph. You write nodes and the relationships between them; it deduplicates, links, and — through a set of autonomous housekeeping agents — merges duplicates, infers new edges, and keeps the hierarchy coherent as the graph grows.

It is domain-agnostic: the same service backs a people graph, a project graph, a code graph, or a general concept graph. And it never calls a language model directly — extraction and synthesis are delegated to the Reasoning engine — so the graph stays a clean, permissioned record of what is known.

How it works

You work in nodes and relationships. A node has a name, a type — people, organisations, concepts and artefacts are the roots — a description, and free-form metadata. Relationships are typed: parent of, contains, implements, related to, extracted from. Writes are idempotent and deduplicated, so the same fact arriving from two systems lands once.

Every request carries your organisation, and the graph you read and write is scoped to it and to no one else's. Nodes can carry an access level — public, internal, confidential or restricted — and search is permission-filtered against it.

Where the intelligence comes from

Cognition OS holds the graph; the Reasoning engine does the thinking. Extraction, embedding and synthesis are delegated, and the results are written back as first-class nodes — so what an agent learns becomes part of the graph the next agent reads.

Your data

Cognition OS stores the nodes and relationships you write, the metadata attached to them, and the embeddings computed for semantic search. Whatever an upstream product sends — for example, a memory Kemory promotes into the graph — becomes graph data and is indexed for search.

Isolation is by organisation and is enforced beneath the query layer: a request cannot read across organisations. Autonomous housekeeping may reshape your graph after a write — merging duplicates or adding inferred edges — and every such change is recorded so it can be traced. How content is retained and erased is set out in the privacy policy.
