Install

Node.js installs the launcher; Docker runs every application service. No host Python, Postgres or Redis installation is required. The launcher needs Kemory Community 0.1.1 or later.

npx kemory-community@latest init --runtime docker
npx kemory-community@latest up

The launcher writes a .kemory-community folder in the current directory, generates a random API key, pulls the published images and starts the pinned Compose stack. Your key is the KEMORY_LOCAL_API_KEY line in .kemory-community/kemory.env. Open the dashboard at http://127.0.0.1:5175 and paste it when asked; the dashboard keeps it in that browser only.

npx kemory-community@latest doctor
npx kemory-community@latest bundle

doctor checks a running install. The bundle command lists the exact required components and the admission gates for optional integrations.

From source

To build the same stack from the repository instead, create the per-install keys first. Compose refuses to start without them; there is no built-in default key.

git clone https://github.com/SeKondBrainAILabs/kemory-community.git
cd kemory-community
printf 'KEMORY_LOCAL_API_KEY=%s\nKEMORY_LOCAL_BLOB_SIGNING_KEY=%s\n' \
  "$(openssl rand -hex 24)" "$(openssl rand -hex 32)" > .env
docker compose -f docker-compose.community.yml up -d --build

Your key is the KEMORY_LOCAL_API_KEY line in .env. Keep that file private: anyone with the key can read and change your memories.

Upgrading from 0.1.0

0.1.0 shipped a published default key. For a source install, create .env as above before the next start, then enter the new key in the dashboard and in your MCP clients. Existing memories are kept; artifact links issued before the upgrade stop working because the signing key changes.

Artifacts use local filesystem storage and telemetry uses the no-op adapter. Runtime data stays in Docker volumes and the local Kemory configuration directory.

Every published port binds to 127.0.0.1. The API answers browser requests only from the dashboard origins in CORS_ORIGINS, and only requests whose Host header is listed in ALLOWED_HOSTS (localhost,127.0.0.1 by default); anything else gets 400. Add your hostname to ALLOWED_HOSTS if you put Kemory behind a reverse proxy.

Connect an agent

Point any MCP client at http://127.0.0.1:8111/mcp/v1 and send your API key in the X-API-Key header. Launcher installs also write a ready-made mcp.json in .kemory-community. Tool discovery advertises canonical kemory_* names; legacy s9nmem_* and kora_* names remain dispatch aliases.

Edition boundaries

Community Edition is an independent downstream repository, not a GitHub fork. Compatible hosted behaviour is selectively ported by feature cohort and tested against the local adapters.

Hosted Keycloak/OIDC, billing, teams and organisations, Gatekeeper evaluation, managed KMS, PostHog, MinIO, Weaviate, FalkorDB, executive analytics and CogOS/L5 runtime paths are not part of Community Edition.

The default bundle does not require Core AI Backend, Core Backend or Keycloak. Scheduled upstream intake detects hosted changes daily, but integration remains reviewed and never automatically crosses the Community boundary.

Privacy

Kemory Community does not send local memories to hosted Kemory and includes no hosted telemetry. External calls occur only for model or embedding providers you explicitly configure, plus the first download of a selected local embedding model.

Keep API keys out of source control and review logs before sharing them publicly.
