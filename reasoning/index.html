What it is

Reasoning is a cognitive backend that sits between your agents and the models. Rather than call a single model and hope, it runs a disciplined three-stage pipeline — route → execute → validate — that picks the right model for the job, runs it, and checks the result against a schema before returning it. Get back validated, structured output, not a paragraph you have to parse.

It is the engine the rest of the platform is built on: memory consolidation, concept synthesis and enrichment all run through it. It is licensed as part of the platform, not a standalone open-source library.

How it works

Your agents reach Reasoning through an MCP server — the same connector model as Kemory — so a Claude-, Cursor- or Codex-style client can call its tools directly: list the skills available, run one, search the reasoning graph, or fetch a product manifest. Requests authenticate with an API key, and your organisation is always derived from that credential, never taken from the request body.

Underneath, the router classifies the task and chooses a model tier; the executor runs it — local-first, with cloud fallback and a circuit breaker so a provider outage degrades gracefully; and the validator checks the output shape. Council mode fans the same prompt out to several models and reconciles their answers.

Local-first by design

Primary inference runs on self-hosted models inside our own cluster. Cloud providers are a fallback, not the default path — which is what keeps latency, cost and data exposure under control at volume.

Your data

Reasoning processes the prompts, conversation turns and embeddings you send it, isolated per organisation. It retains conversation and usage records so you can see what ran and what it cost. Every request is scoped to the organisation on its credential.

Inference is local-first: your content is reasoned over by self-hosted models by default. When a request falls back to a cloud provider — or you configure one deliberately — that prompt content leaves to that third party; which providers, and what they retain, is set out in the privacy policy.
